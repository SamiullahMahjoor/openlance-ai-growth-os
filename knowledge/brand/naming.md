# Open Lance Naming Standard

This document owns the Naming standard for Open Lance: the convention for naming what the organization presents. It is a brand standard document within the Brand namespace, and it follows the Brand Document Standard defined in knowledge/brand/README.md. The definition of the term Naming is owned by knowledge/brand/README.md; this document owns the convention only. The names of specific things are owned by their canonical documents, and this standard governs how names are formed and used, not what any particular thing is called. Where this document and a higher-authority document differ, the higher-authority document governs.

# Purpose

This document owns the standard for how Open Lance names things in outward communication. Its purpose is that names stay clear, consistent, and stable, so a reader always recognizes the same thing by the same name and understands a name on sight.

# Standard

Open Lance forms and uses names by the following durable rules.

- Use the canonical name. Anything the repository already names is referred to by the canonical name owned by its document. Brand communication never invents an alternate or marketing name for a thing that already has one.
- The organization's own name. The organization's name is used in the full canonical form owned by knowledge/company/company.md. It is not abbreviated, contracted, restyled, or run together in brand communication.
- New names are plain and descriptive. When something genuinely new must be named, the name plainly describes what the thing is, consistent with the vocabulary standard owned by knowledge/brand/vocabulary.md. Invented, trademark-style, or hype names are avoided where a plain name works.
- One name, one thing. Each thing keeps a single name, and a single name refers to a single thing. A concept is never given two names, and one name is never reused for two concepts.
- Clarity over cleverness. A name a reader must have explained is usually the wrong name. Prefer names understood on sight.
- Stability. A canonical name, once set, is used consistently and not casually changed. A change to a canonical name follows the amendment process of the document that owns it.

# Rationale

Naming carries the organization's promise of simplicity and transparency, owned by knowledge/company/principles.md, into the smallest unit of communication. A user should know what a thing is from its name, which is why names stay plain and descriptive. One name per thing mirrors the repository's own single-source-of-truth discipline defined in knowledge/README.md, so that the way the organization talks about itself never drifts from the way the repository defines itself.

# Application

The naming standard applies to every outward communication in every medium. When a name is needed, a writer or agent first checks whether a canonical name already exists and uses it, and only forms a new name when nothing canonical exists, following the rules above. This document states the naming convention; it holds no list of specific names, which live with their owners, and it never writes a specific piece of content, which is an Output.

# Boundaries

This document owns the naming convention only. It owns none of the following.

- The definition of the term Naming: knowledge/brand/README.md.
- The organization's name and identity: knowledge/company/company.md.
- The canonical names of roles, entities, capabilities, and states: their documents under knowledge/product/ and elsewhere in the repository.
- Word choice for non-name language: knowledge/brand/vocabulary.md.
- Voice and tone: knowledge/brand/voice.md and knowledge/brand/tone.md.
- What the organization says it offers: knowledge/brand/messaging.md, and the facts owned by knowledge/company/ and knowledge/product/.
- Marketing and campaign naming strategy: the Marketing namespace, knowledge/marketing/.
- Domains, handles, slugs, code identifiers, and other technical identifiers: the codebase and operations systems, not the knowledge repository.
- Trademark and legal constraints on names: the legal documents in their owning folders.
